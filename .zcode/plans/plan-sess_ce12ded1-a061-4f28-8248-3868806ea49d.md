## Plan: Improve Receipt OCR Parsing Accuracy

### Summary of Issues & Decisions

| Issue | Decision |
|---|---|
| Amount misinterpretation | 4-strategy approach: keyword lines, largest number, position-based, font-size analysis |
| Thousand separator | Auto-detect dot vs comma from context; accept both `1.000` and `1,000` |
| Decimal detection | Last 2 digits with different separator = decimal (`1.000,00` or `1,000.00`) |
| "Transaksi Berhasil" | Skip as description source; use merchant/items instead |
| "Transaksi Gagal" | **Auto-reject** — show error screen with retry/cancel, do not proceed to review page |
| From/To detection | DARI/KE labels, Transfer ke/dari keywords, receipt type implies direction, account/phone matching |

### Files Modified

#### 1. MODIFY: `src/lib/ocr-engine.ts` — Add font-size aware extraction

Add `recognizeReceiptWithBlocks()` that returns both raw text AND text blocks with estimated font size from Tesseract word-level bounding boxes:

```typescript
interface OcrBlock {
  text: string;
  fontSize: number; // estimated from bounding box height
  y: number;        // vertical position (pixels from top)
  x: number;        // horizontal position
}
```

Uses Tesseract's `worker.recognize()` word-level data → groups by line → estimates font size from bounding box height. Enables identifying which numbers are printed larger (likely the total) and vertical position (bottom = likely total).

#### 2. MODIFY: `src/lib/keyword-map.ts` — Robust amount parsing + failed detection

**New: `detectTransactionFailed()`**:
```typescript
export function detectTransactionFailed(text: string): boolean {
  const lower = text.toLowerCase();
  return lower.includes('transaksi gagal') ||
         lower.includes('transaction failed') ||
         lower.includes('pembayaran gagal') ||
         lower.includes('payment failed');
}
```

**New: `extractAmountSmart()`** — 4 cascading strategies:

1. **Total keyword lines** — search for `TOTAL`, `TOTAL BAYAR`, `GRAND TOTAL`, `JUMLAH`, `NOMINAL`; if multiple found, prefer the last one (final total)
2. **Largest font-size number** — using `OcrBlock.fontSize`, find numbers with biggest font, pick one nearest total keyword or at bottom
3. **Bottom 30% position** — using `OcrBlock.y`, largest number in bottom zone
4. **Largest number anywhere** — fallback

**New: `parseSmartAmount()`** — auto-detect separator + strip decimal:
- Pattern `X.XXX.XXX` → dot = thousand separator
- Pattern `X,XXX,XXX` → comma = thousand separator
- Pattern `X.XXX,XX` → dot = thousand, comma = decimal
- Pattern `X,XXX.XX` → comma = thousand, dot = decimal
- Strip the decimal portion (last 2 digits after different separator)

**New: `extractFromTo()`** — extract DARI/KE, Transfer ke/dari, Pengirim/Penerima for direction detection.

**Modified: `extractCounterparty()`** — skip "Transaksi Berhasil"/"Transaksi Gagal" headers as merchant name candidates.

#### 3. MODIFY: `src/app/api/ai/parse-receipt/route.ts` — Use smart extraction, add failed flag

- Accept optional `blocks` array in request body
- **Check `detectTransactionFailed()` first** — if failed, return `{ failed: true }` immediately (no AI call)
- Use `extractAmountSmart()` with blocks for better amount extraction in local fallback
- AI system prompt updated: ignore "Transaksi Berhasil" as description, use DARI/KE for direction, prefer total keyword lines
