## Plan: Fix OCR Amount Extraction — Prioritize Rp/IDR-Prefixed Amounts

### Root Cause
The current 4-strategy cascade prioritizes "TOTAL" keywords and "largest font/number" — but **never prioritizes the strongest signal: amounts with Rp/IDR currency prefix**. On banking screenshots, the actual amount (e.g. `Rp 1.250.000`) is often NOT the largest number on the receipt (account numbers, phone numbers, transaction refs are bigger). It may also NOT be the largest font. But it almost always has an `Rp` or `IDR` prefix — the undisputable element.

### Strategy Reorder (new priority order)

#### `src/lib/keyword-map.ts` — `extractAmountSmart()`

**New Strategy 1: Rp/IDR-prefixed amounts** (HIGHEST PRIORITY)
- Scan ALL lines for amounts with `Rp`/`IDR` prefix
- If multiple found (e.g. `Rp 25.000` item + `Rp 50.000` total), prefer the **largest** one (usually the total)
- If multiple same amounts, prefer the **last one found** (bottom of receipt = likely total)
- Also check the line AFTER a keyword match (e.g. `NOMINAL\nRp 50.000`)

**New Strategy 2: Total/amount keyword lines** (current Strategy 1)
- Keep existing TOTAL_KEYWORDS scan but expanded with: `besar`, `jumlah transfer`, `nominal transfer`, `pembayaran`, `biaya`, `kredit`, `debit`
- Fix: check keyword line AND the line below it

**Strategy 3: Largest font-size Rp/IDR amount** (current Strategy 2, filtered)
- Only consider blocks that contain Rp/IDR-prefixed amounts (not any number)

**Strategy 4: Bottom 30% Rp/IDR amount** (current Strategy 3, filtered)  
- Only consider blocks in bottom zone that have Rp/IDR prefix

**Strategy 5: Largest Rp/IDR amount anywhere** (filtered version of current Strategy 4)

**Strategy 6 (fallback): Largest formatted number anywhere** (current Strategy 4, unchanged)
- For receipts with NO currency prefix at all

#### `src/lib/keyword-map.ts` — `parseSmartAmount()` fix
- Fix currency stripping regex from `[RpRpIDRidr$¥€£\s]` to `(?:[Rr][Pp]\.?|IDR|idr|\$|¥|€|£)` and strip trailing `,-`

#### `src/lib/keyword-map.ts` — `extractCounterparty()` fix
- Add skip patterns: `forwarded`, bank app names (`bca mobile`, `bri mobile`, `bni mobile`, `mandiri`, `dana`, `gopay`, `ovo`, `shopeepay`), chat headers
- For banking receipts (no QRIS, no "Toko"/"Store"/"Merchant"), look for sender/recipient name AFTER "DARI"/"KE" labels instead of the first short line

#### `src/app/api/ai/parse-receipt/route.ts` — Pass block data to AI
- Include top 30 blocks (text + fontSize + y) in the AI user message
- Update prompt: "use the block data below to identify which number is the transaction amount"
- This makes the AI prompt's font-size instructions actually actionable
